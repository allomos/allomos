Vibe Coding 的来龙去脉，散落在上百个对话里

一个项目要经过很多会话：Claude Code、Codex、好几个账号、好几个人。额度可能毫无预警地让会话中断，下一个会话只能从零开始，当初的决定只留在某段旧对话里。在一个真实的多智能体项目里：

  • 185 KB 的交接文档，每个新会话接手都得从头读一遍；
  • 6 个地方要手工同步同一个任务的状态；
  • 3 个会话同时抢任务，最后靠 Git 合并冲突来裁决；
  • 0 人能回答“到底什么时候能做完？”

任务管理：没有什么藏在对话里

任务就是 .allomos/taskbag/ 下可读的普通文件，用你自己的 Git 管理版本，不锁在某个智能体的记忆或某个账号里。任务包记下的是：

  • 每个任务和它的状态——就绪、进行中、等待、受阻、完成——集中在一处，同一时间只有一个人（或智能体）负责。
  • 逐级验证的进展——每个任务沿着阶梯往上走（已实现 → 本地验证 → 已部署 → 人工确认），进度靠证明，不靠口头声称。
  • 交接笔记和 AI 自己做的决定——做了什么、下一步是什么，以及智能体做过的每个日常选择，方便你事后审查。
  • 你的待办清单——需要你确认、回答或审查的事项，一张表全列出来。

几个月后，你或新来的队友回头看代码时，每处改动背后的原因都还在。

应用里的新功能

  • 构建新应用…——描述你想要的应用，智能体把它拆成一组任务，一个接一个做完。勾选先讨论，可以在开工前先和智能体把想法聊清楚。
  • 用手机看任务——打开网络中的设备…，同一网络里的手机或另一台电脑就能查看和修改任务。
  • 一个任务包，多个项目文件夹——由多个代码仓库组成的应用，也只用一份任务列表。
  • 任务包以标签页打开——像浏览器一样，一个窗口里开多个项目，还能把标签页拖到另一个窗口。
