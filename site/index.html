Vibe coding leaves its history in a hundred chats

A project moves through many sessions: Claude Code, Codex, several accounts, several people. A quota can end a session without warning; the next one starts cold, and what was decided lives only in an old conversation. In one real multi-agent project:

  • 185 KB of handoff notes that each new session re-read to resume;
  • 6 places where one task's status was copied by hand;
  • 3 sessions claiming tasks at once, settled by merge conflict;
  • 0 answers to “when will it be done?”

Switching: Claude runs out, Codex picks up

Every agent uses the same alm commands. One step to hand over, one step to take over — between agents, between accounts, between people. The next session reads the task and its note, not a 185 KB history.

# Claude Code · account 1 · quota nearly used
alm label A01-03 "implemented"
alm release A01-03 --note "form done; tests next"

# Codex · account 2 · a minute later
alm next
A01-03  Sign-in page  ready · note: tests next
alm claim A01-03

Task management: nothing hides in a chat

Tasks live as readable files in .allomos/taskbag/, versioned by your own Git — not inside one agent's memory or one account. What the taskbag keeps:

  • Every task and its state — ready, in progress, waiting, blocked, done — in one place, with one owner at a time.
  • Proven steps — each task climbs a ladder (implemented → locally verified → deployed → checked by a person), so progress is shown, not claimed.
  • Handoff notes and the AI's own decisions — what was done, what's next, and every routine choice the agent made, so you can review them later.
  • A queue for you — what needs your check, your answer or your review, in one list.

Months later, when you or a new teammate come back to the code, the reason behind each change is still there.

AI skills In development
