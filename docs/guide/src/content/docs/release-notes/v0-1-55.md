Released 2026-11-11. [Download from GitHub](https://github.com/allomos/allomos/releases/tag/v0.1.55).

## New

- **Hand a task to another agent.** A task's pane now has **Hand over to another agent…** while a session holds it. The dialog takes three steps: choose the new agent (its 5-hour quota left shows under the list), press **Ask for the handoff**, then wait while the current session writes its handoff note and lets the task go. The session hears of the request the next time it runs `alm`; to reach it sooner, press **Open its session** or **Copy the request** and paste it there. Once the task is released, the dialog shows the handoff note and **Open** starts the new agent on the same working branch. If nothing happens for more than one heartbeat, it offers **Take over…** instead.
- **Take over any held task.** **Take over…** is now in the pane of every held task that is not finished, not only lost ones. When the holder is still sending heartbeats, the dialog says so, with the last heartbeat and the working branch, warns that both sessions might work on the same branch for a while, and its button reads **Take over anyway**. In the task list, only lost tasks show the button, as before.
- **Know how far an interrupted task got, on any computer.** A session can say what it is doing with each heartbeat (`alm beat --doing "…"`); it shows in the pane's **Last heartbeat** row, in `alm next` and `alm show`, and in the takeover dialog. While a project's new setting **Push work in progress at each heartbeat, to prepare for a takeover** is on (**Settings › Heartbeat**, on by default, or `alm heartbeat-settings`), `alm beat` reminds the session to commit and push its unfinished work, so a takeover on another computer loses at most one heartbeat of it. The takeover dialog and `alm claim` now say that only what was pushed counts.

## Also

- **Updated agent rules.** The rules Allomos writes into a project's AGENTS.md describe handing over, taking over a task that is not lost, and pushing work in progress.
