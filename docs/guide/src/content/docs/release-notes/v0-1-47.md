Released 2026-11-09. [Download from GitHub](https://github.com/allomos/allomos/releases/tag/v0.1.47).

## New

- **Allomos's rules for Codex.** With Codex chosen in **Monitor ready tasks**, the dialog offers **Let Codex run Git and alm without asking**, checked by default. It adds Allomos's rules file for Codex (`~/.codex/rules/allomos.rules`): each unattended Codex session can then pull, commit, push and merge, and run alm, without asking, while every other command stays in Codex's sandbox. This replaces the earlier advice to give Codex full access. Nothing is written until you press **Start**, which writes or removes the file and records it in the project's history; your own rules in `default.rules` are never touched. When Allomos's rules are older, or someone changed the file, the dialog says which commands are added and removed before anything changes; a file from a newer Allomos is left as it is. `alm guide codex-rules` prints the rules, `alm guide agent-files` has Codex's once-per-computer step, and `alm guide workflow` says what to do when Git cannot write the checkout.

## Fixed

- **A session that comes back after its task was finished.** When a task was taken over and the new session has since finished it (done or dropped), the former session is now still told who took it over and finished it, and its changes are refused. `alm release` of a done or dropped task is refused for every session and points to `alm reopen`, so it can no longer erase the holder.
