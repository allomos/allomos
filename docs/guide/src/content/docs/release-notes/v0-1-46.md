Released 2026-11-09. [Download from GitHub](https://github.com/allomos/allomos/releases/tag/v0.1.46).

## New

- **Heartbeats.** A session holding a task now shows it is still at work: `alm beat` writes a heartbeat on the task (with no ID, on every task the session holds), and every change the holder makes to its task beats along. `alm beat --busy <how long>` declares a busy window, for long work that cannot beat. Heartbeats write no event, so the burndown and the timeline are unchanged.
- **Lost tasks.** The task list and the task pane show each held task's **Last heartbeat** (or **busy until …**). A held task with no heartbeat for longer than the lost limit, and no busy window running, gets an amber **Lost** tag. `alm next` lists such tasks under *Lost, can be taken over*, each with the command to take it over; alm only lists them and takes nothing over by itself.
- **Taking over a lost task.** `alm claim` on a lost task takes it over and goes on on its working branch, recording the former holder; a held task that is not lost is still refused. In the app, a lost task's row offers **Take over…**, which opens a new AI agent session to do this. A session that comes back is told its task was taken over, and its further changes to that task are refused.
- **Settings → Heartbeat.** The taskbag's settings have a **Heartbeat** section with the **Heartbeat interval** (10 minutes by default) and **Lost after** (30 minutes by default), and **Back to the defaults**. With alm: `alm heartbeat-settings`.
- **Shared rules for heartbeats.** The shared rules alm writes into AGENTS.md now tell every agent to pass `--as`, beat every 10 minutes, declare `--busy` for long work, take over lost tasks and stop when its own task is taken over. `alm guide agent-files` has a new step for setting up an automatic heartbeat (a hook in the agent's own project settings), done only with the person's approval.
- **Two sessions claiming one task at once.** The session that loses the race is told whose task it is, with its last heartbeat and how to drop its own claim, and which ready task is next.
- **Quota from Claude Code terminal sessions.** Claude Code sessions started by **Monitor ready tasks** read their quota with `claude -p /usage` and report it, so the header shows a current figure for them too.

## Fixed

- **The settings dialog scrolls.** A long section no longer runs under **Close**: the section list and the section scroll on their own, and the last items can be reached.
- **The quota popup shows one row per agent, account and window.** Refreshed rows no longer linger beside the new ones, and a new report replaces the ones saved under old session names.
