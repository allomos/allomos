監査人はどの変更についても四つのことを尋ねます。**誰が**したか、**誰の承認で**したか、**確認されたか**、そして**記録が後から書き換えられた可能性はないか**。「肩代」はこれに答える記録を、タスクバッグの履歴（変更ごとに一つの小さなファイル）に残します。

このページでは、「肩代」がそれ自体で記録するもの、**設定 → タスクバッグ → 監査**の各設定が加えるもの、よくある規格ごとにオンにする設定を説明します。

:::note[「肩代」は助けるもので、認証するものではありません]
「肩代」はツールです。会社の統制を**支援し**、規格を**満たす助けになります**が、プロジェクトを「準拠」させるものではありません。監査人が認証するのは会社の取り組み全体であり、ツールではありません。「肩代」は FDA 21 CFR Part 11 を満たすとは主張しません。Part 11 には会社自身のシステムバリデーション文書も必要だからです。
:::

## 常に記録

設定は不要で、オフにもできません。コストは小さく、一人で使うプロジェクトにも役立ちます。

| 何を | 残すもの |
|---|---|
| **誰がしたか** | エージェントなら、どのエージェント・モデル・セッションか、誰のために作業しているか。人なら、仮名 ID（[本人確認](#本人確認) を参照）。 |
| **承認** | 誰が、どのタスクとどの計画を、いつ、どの経路で、どんな言葉で承認したか。いつ失効したか、取り消されたか。 |
| **人の確認** | 誰が、どの版の確認手順で確認したか、結果（合格、不合格、一部）と書いた言葉。 |
| **署名された変更** | 各コンピューターは自分が書く変更に署名し、チェックポイントがタスクバッグ全体の指紋を固定します。後から変更を消したり書き換えたりすると、`alm audit` に表れます。 |
| **コードへのリンク** | タスクに伴うコミット、ブランチ、マージ、プルリクエスト、CI の実行、リリース。 |
| **外部への影響** | 外部のシステムに触れた操作（デプロイなど）：対象、操作、元に戻す方法、承認と結果。 |
| **変更の種類とリスク** | 標準・通常・緊急、リスクの低・中・高。緊急の変更は承認を後から記録します。 |
| **理由** | タスクを移した、取りやめた、計画を変えた理由。 |
| **例外** | 実行しなかったチェックや人の確認なしで終えたタスク、その理由、そしてそのリスクを誰が受け入れたか。 |
| **AI の情報** | 正確なモデル ID、effort、権限モード、ルール（`AGENTS.md`）と `alm` のバージョン。エージェントが知り得ないものは推測せず "unknown" と書きます。 |
| **トレーサビリティ** | タスクが対応する要件と決定。 |

## 監査の設定

**設定 → タスクバッグ → 監査**（タスクバッグ名の横から設定を開きます）。設定はタスクバッグに保存されるので、プロジェクトの全員が同じルールで作業します。設定の変更自体も理由とともに記録されます。統制をオフにするときは警告色で表示され、理由が必要です。

### 本人確認

各変更の背後にいる人の身元をどこから得るか：

- **仮名**（既定）：履歴には仮名 ID だけが残ります。その背後が誰かは、タスクバッグの外、このコンピューターに保存されます。
- **Allomos アカウント**：クラウドプロジェクトのアカウント。クラウドプロジェクトが必要です。
- **会社のサインイン（SSO）**：会社の ID プロバイダー（OpenID Connect または SAML 2.0）。クラウドプロジェクトが必要です。
- **承認や確認のたびにサインインし直す**：承認と人の確認のたびに、新たにサインインします（アカウントまたは SSO のときのみ）。

### 職務の分離

オンにすると、同じ人またはエージェントが同じタスクを作業して確認する、または作業して承認することはできず、`alm` とアプリが拒否します。一人のプロジェクトではタスクを一つも終えられなくなるため、既定はオフです。

### 外部のタイムスタンプ証人

オンにすると、タイムスタンプサービス（RFC 3161）が各チェックポイントの指紋に副署し、履歴がその時点でその形で存在したことを示せます。**送るのは指紋だけで、タスクバッグの内容は決して送りません。** サービス（タイムスタンプごとに料金がかかるものもあります）と頻度（毎日、承認と人の確認のたび、または頼んだときだけ）を選びます。外部サービスにデータを送るため、既定はオフです。

### 保存

履歴を保存する期間（無期限、または何年か）と、何も削除できなくなる**訴訟ホールド**。**個人情報を消去…**は、タスクから選んだ項目を削除し、何をなぜ削除したかの記録を古い値なしで残します。

### 変更の種類

固定の変更の種類とリスクの段階、その意味を表示します。設定するものはありません。

## 規格ごとに必要な設定

下の表は、ニーズごとに、それを求める条項、「肩代」で役立つもの、オンにするものを示します。「常にオン」はオンにするものがないという意味です。

| ニーズ | 規格と条項 | 「肩代」で役立つもの | オンにする |
|---|---|---|---|
| 変更が認可・テスト・承認されている | ISO/IEC 27001:2022 附属書 A **8.32** 変更管理、SOC 2 **CC8.1**、SOX 404 条（15 U.S.C. 7262）と PCAOB **AS 2201** | 承認、変更の種類、コミットと CI へのリンク、理由 | 常にオン |
| 誰がいつ何をし、結果がどうだったかのログ | ISO/IEC 27001 **8.15** ログ取得、**8.16** 監視活動、SOC 2 **CC7.2**、GB/T 22239-2019（等保 2.0）第 3 級 **8.1.4.3** a)–b) と **8.1.3.5**、21 CFR **11.10(e)** | 誰がしたか、すべての変更 | 常にオン |
| 記録が削除や改ざんから守られている | ISO/IEC 27001 **5.33** 記録の保護、GB/T 22239-2019 **8.1.4.3** c)–d)、21 CFR **11.10(e)** | 署名された変更、チェックポイント | 常にオン。**外部のタイムスタンプ証人**を推奨 |
| 信頼できる時刻 | ISO/IEC 27001 **8.17** クロックの同期、eIDAS（規則 (EU) 910/2014、2024/1183 による改正後）**第 41–42 条**、定義は**第 3 条 (33)–(34)** | 外部のタイムスタンプ証人 | **外部のタイムスタンプ証人**（eIDAS では EU トラストリストの適格事業者） |
| 職務の分離 | ISO/IEC 27001 **5.3** 職務の分離 | 職務の分離 | **職務の分離** |
| ID と認証 | ISO/IEC 27001 **5.16** 識別情報の管理、**8.5** セキュリティを保った認証、SOC 2 **CC6.1–CC6.3**、NIST SP 800-63-4 | 本人確認の段階 | **本人確認**：Allomos アカウントまたは会社のサインイン（SSO） |
| 記録に結び付いた電子署名 | 21 CFR **11.50**、**11.70**、**11.200(a)(1)**、中国の電子署名法（电子签名法）**第 13–14 条** | サインインし直す承認と人の確認 | **本人確認**：SSO と**承認や確認のたびにサインインし直す** |
| ログの保存 | 中国のサイバーセキュリティ法（网络安全法）**第 23 条 (3)**：ネットワークログを 6 か月以上保存、SEC 規則 S-X **Rule 2-06**（17 CFR 210.2-06）：監査人は監査記録を 7 年保存（18 U.S.C. 1520 も参照） | 保存、訴訟ホールド | **保存**（少なくとも自社の規則が求める期間） |

### 規格別の早見

- **ISO/IEC 27001:2022**：常にオンのものに加え、**外部のタイムスタンプ証人**（8.17）、**職務の分離**（5.3）、アカウントか SSO の**本人確認**（5.16、8.5）。
- **SOC 2**：常にオンのもの（CC7.2、CC8.1）に加え、アカウントか SSO の**本人確認**（CC6.1–CC6.3）。
- **等保 2.0（GB/T 22239-2019）第 3 級**：常にオンのものに加え、**外部のタイムスタンプ証人**を推奨（8.1.4.3 c)）。サイバーセキュリティ法に従い**保存**を 6 か月以上に。
- **SOX（IT 全般統制）**：常にオンのもの（変更管理）に加え、監査記録に足りる長さの**保存**（Rule 2-06 では 7 年）。
- **21 CFR Part 11**：常にオンのものに加え、SSO の**本人確認** と**承認や確認のたびにサインインし直す**。11.10(a) のシステムバリデーションは会社自身の作業で、「肩代」は Part 11 を主張しません。
- **eIDAS のタイムスタンプ**：適格事業者を選んだ**外部のタイムスタンプ証人**。

## この表について

- 条項番号は 2026-11-09 に一つずつ確認しました。法令（中国のサイバーセキュリティ法と電子署名法、21 CFR Part 11、eIDAS、17 CFR 210.2-06、18 U.S.C. 1520、15 U.S.C. 7262）と NIST SP 800-63-4 は公式の原文で、ISO/IEC 27001 附属書 A は同じ番号を使う ISO/IEC 27002:2022 の公式目次で、GB/T 22239-2019 は規格の全文の写し（公式の規格情報ページは開けませんでした）で、SOC 2 の基準は AICPA の原文にサインインが必要なため二次資料でのみ確認しました。監査がある条項に依拠する場合は、お手元の全文で確認してください。
- SOC 2 の番号は 2017 年版トラストサービス規準（2022 年改訂の着眼点）によります。AICPA は 2026-10-28 に 2027 年版の新規準の公開草案を出しました。採択されたらこの表を確認し直します。
- ISO/IEC 27001:2022/Amd 1:2024（気候変動対策）は附属書 A を変えていません。
- 中国のサイバーセキュリティ法の改正は 2026-01-01 施行で、6 か月のログ保存の規定は改正前は第 21 条でした。
- 記録そのものを確認するには `alm audit` を実行します。見つけた事実（署名のない変更、切れたチェーン、空白、合わない受領証）を一覧にし、判断はあなたに委ねます。
