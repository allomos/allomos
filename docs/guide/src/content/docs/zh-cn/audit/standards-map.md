审计员对每一次改动都会问四件事：**谁**做的、**依据谁的批准**、**有没有检查过**、**记录事后能不能被改**。「换肩」把能回答这四个问题的记录保存在任务袋的历史里（每次改动一个小文件）。

这一页说明「换肩」自己一直记录什么、**项目设置 → 审计**里的每一项另外加了什么，以及几种常见标准各要打开哪几项。

:::note[「换肩」是帮助，不是认证]
「换肩」是一个工具。它**支持**公司的控制措施，**有助于满足**某个标准；它从不让一个项目“符合”标准。审计员认证的是公司的整套做法，不是一个工具。「换肩」不声称满足 FDA 21 CFR Part 11，因为它还要求公司自己的系统验证文件。
:::

## 一直记录

这些不用设置，也不能关掉。它们代价很小，对一个人用的项目也有用。

| 什么 | 记下什么 |
|---|---|
| **谁做的** | agent：哪个 agent、模型和会话，以及它替哪个人做。人：一个化名 ID（见[身份](#身份)）。 |
| **批准** | 谁批准、批准的是哪些任务和哪一版计划、什么时候、通过什么渠道、原话，以及何时失效或撤回。 |
| **人工验证** | 谁验证、按哪一版检查步骤、结果（通过、不通过、部分通过）和写下的话。 |
| **签名的改动** | 每台电脑给自己写的改动签名；检查点固定整个任务袋的指纹。事后删掉或改动一次改动，`alm audit` 会列出来。 |
| **关联代码** | 和任务一起的提交、分支、合并、PR、CI 运行和发布。 |
| **外部影响** | 动到外部系统的操作（例如部署）：目标、动作、怎么撤回、依据的批准和结果。 |
| **变更类型和风险** | 标准、常规或紧急；低、中、高风险。紧急变更事后补记批准。 |
| **原因** | 任务为什么被移动、放弃或改计划。 |
| **例外** | 没跑的检查、没经人工验证就完成的任务、为什么，以及谁接受了这个风险。 |
| **AI 信息** | 准确的模型 ID、effort、权限模式、规则（`AGENTS.md`）和 `alm` 的版本。agent 无法知道的写成 "unknown"，从不猜。 |
| **追溯** | 任务服务的需求和决策。 |

## 审计设置

**项目设置 → 审计**（在任务袋名字旁边打开设置）。这些设置存在任务袋里，项目里的每个人都按同一套规则工作。改其中任何一项本身也会被记录，并写明原因；关掉一项控制时显示为警示色，必须写原因。

### 身份

每次改动背后的身份从哪里来：

- **化名**（默认）：历史里只有化名 ID。化名背后是谁，保存在这台电脑上，不在任务袋里。
- **Allomos 账号**：云项目的账号。需要云项目。
- **企业登录（SSO）**：公司的身份提供方（OpenID Connect 或 SAML 2.0）。需要云项目。
- **批准或验证时重新登录**：每次批准和人工验证都要重新登录（只在用账号或 SSO 时）。

### 职责分离

打开后，同一个人或 agent 不能对同一个任务既做又验证，或既做又批准：`alm` 和应用会拒绝。默认关闭，因为只有一个人的项目将无法完成任何任务。

### 外部时间戳见证

打开后，时间戳服务（RFC 3161）给每个检查点的指纹回签，能证明历史在那个时间已经是这个样子。**只发送指纹，从不发送任务袋的内容。** 由你选择服务（有的服务按次收费）和多久一次：每天、每次批准和人工验证时，或只在你要求时。默认关闭，因为它要把数据发给外部服务。

### 保留

历史保留多久（永久，或若干年），以及**法律保全**：保全期间什么都不能删除。**清除个人信息…**从任务里删掉选定的字段，并留下一条记录，写明删了什么和为什么，但不留旧值。

### 变更类型

显示固定的变更类型和风险等级及其含义。没有要设置的。

## 标准对照表：各标准要打开哪几项

下表按需求列出：哪些条款要求它、「换肩」里什么有帮助、要打开什么。“一直开着”表示不用打开什么。

| 需求 | 标准和条款 | 「换肩」里有帮助的 | 要打开 |
|---|---|---|---|
| 变更经过授权、测试和批准 | ISO/IEC 27001:2022 附录 A **8.32** 变更管理；SOC 2 **CC8.1**；SOX 第 404 条（15 U.S.C. 7262）及 PCAOB **AS 2201** | 批准、变更类型、关联提交和 CI、原因 | 一直开着 |
| 记录谁在何时做了什么、结果如何 | ISO/IEC 27001 **8.15** 日志、**8.16** 监视活动；SOC 2 **CC7.2**；GB/T 22239-2019（等保 2.0）第三级 **8.1.4.3** a)–b) 和 **8.1.3.5**；21 CFR **11.10(e)** | 谁做的、每一次改动 | 一直开着 |
| 记录不被删除或改动 | ISO/IEC 27001 **5.33** 记录的保护；GB/T 22239-2019 **8.1.4.3** c)–d)；21 CFR **11.10(e)** | 签名的改动、检查点 | 一直开着；建议打开**外部时间戳见证** |
| 可信时间 | ISO/IEC 27001 **8.17** 时钟同步；eIDAS（条例 (EU) 910/2014，经 2024/1183 修订）**第 41–42 条**，定义见**第 3 条第 (33)–(34) 项** | 外部时间戳见证 | **外部时间戳见证**（eIDAS 要选欧盟可信列表上的合格服务商） |
| 职责分离 | ISO/IEC 27001 **5.3** 职责分离 | 职责分离 | **职责分离** |
| 身份和认证 | ISO/IEC 27001 **5.16** 身份管理、**8.5** 安全认证；SOC 2 **CC6.1–CC6.3**；NIST SP 800-63-4 | 身份级别 | **身份**：Allomos 账号或企业登录（SSO） |
| 电子签名与记录相关联 | 21 CFR **11.50**、**11.70**、**11.200(a)(1)**；《电子签名法》**第十三条、第十四条** | 带重新登录的批准和人工验证 | **身份**：SSO，并打开**批准或验证时重新登录** |
| 日志保留 | 《网络安全法》**第二十三条第（三）项**：网络日志至少留存六个月；美国证监会 S-X 条例 **Rule 2-06**（17 CFR 210.2-06）：审计师的审计记录保存七年（另见 18 U.S.C. 1520） | 保留、法律保全 | **保留**（至少按你们的规定） |

### 按标准速查

- **ISO/IEC 27001:2022**：一直开着的，加上**外部时间戳见证**（8.17）、**职责分离**（5.3）、**身份**用账号或 SSO（5.16、8.5）。
- **SOC 2**：一直开着的（CC7.2、CC8.1），加上**身份**用账号或 SSO（CC6.1–CC6.3）。
- **等保 2.0（GB/T 22239-2019）第三级**：一直开着的，建议加上**外部时间戳见证**（8.1.4.3 c)），并按《网络安全法》把**保留**设为至少六个月。
- **SOX（IT 一般控制）**：一直开着的（变更管理），加上足够长的**保留**以存放审计记录（Rule 2-06 要求七年）。
- **21 CFR Part 11**：一直开着的，加上**身份**用 SSO 和**批准或验证时重新登录**。11.10(a) 的系统验证是公司自己的工作；「换肩」不声称满足 Part 11。
- **eIDAS 时间戳**：**外部时间戳见证**，选合格服务商。

- 《网络安全法》的修订自 2026-01-01 起施行；六个月留存日志的规定此前是第二十一条。
