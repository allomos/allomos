发布于 2026-11-08。[在 GitHub 下载](https://github.com/allomos/allomos/releases/tag/v0.1.43)。

## 新增

- **历史写明谁做的、替谁做、依据哪条批准、为什么。** 现在每次改动都记下是谁做的：人用化名，智能体记下它的会话、模型、effort、权限模式、规则版本和 `alm` 版本；也记下替谁做、依据哪条批准。`alm --why "<原因>"` 写明原因；状态变化或改计划没写原因时，`alm` 会指出。
- **批准成为记录。** `alm approve` 记下谁批准了哪份计划、何时、在哪里、到何时为止；`alm withdraw` 撤回一条。任务面板有 **批准** 一栏，显示每条批准是否仍然有效，还是已过期、已撤回，或因描述改了而不再对得上。**批准…** 在你批准之前按原文显示计划；储备中的任务还有 **批准并设为就绪**；**撤回…** 会问原因。批准不改变任务的状态。
- **人工验证记下谁、按哪一版步骤、结果如何。** **已检查** 和 `alm checked` 记下验证人、所按的检查步骤版本、结果（`--result pass` 或 `partly`）和原话（`--words`）。
- **例外都有记录。** 没跑的检查、不做人工检查就完成的任务，都记下原因和接受风险的人：`alm exception`，用 `alm exceptions` 列出。`alm done --without-human-check` 会自己记一条。
- **变更类型和风险。** `alm classify` 记下任务的变更类型（标准、常规或紧急）、风险和影响范围。紧急变更在有人补上批准之前，列在 `alm human` 的 **To approve afterwards**（待补批准） 下。
- **任务关联到代码、发布、需求和决策。** `alm link` 记下任务的提交、分支、合并、PR、CI 运行和发布，`alm links` 能从其中任何一个反查任务；任务面板在 **代码和发布** 下列出。`alm trace` 把任务关联到需求编号和决策记录，`alm traces` 找出对应的任务。
- **外部影响有台账。** `alm effect` 在每个外部影响发生之前记下目标、动作、怎样回滚、依据哪条批准，之后补上结果；`alm effects` 列出它们，任务面板在 **外部影响** 下显示。
- **签名的历史和 alm audit。** 在新的任务袋格式 `allomos/8` 中，每台电脑用自己的密钥（存在 macOS 钥匙串里）为它写的事件签名，并连成链。`alm checkpoint` 保存任务袋的签名指纹，`alm audit` 列出被改动、被删掉或没有签名的事件。新建的任务袋直接是 `allomos/8`。`allomos/7` 的任务袋照旧可用、不签名，直到你运行 `alm upgrade`。升级之后，Allomos 0.1.42 及更早的版本不能再写入它，所以请先在每台处理它的电脑上装好 0.1.43。
- **项目设置 → 审计。** 四项设置，每次改动都带原因记入历史。**身份**：历史里只有化名；Allomos 账号和企业登录（SSO）需要云端项目，暂不可用。**保留**：历史保留多久；Allomos 从不自己删除任何内容。**法律保全**：开启期间什么都不能删除。**职责分离**：默认关闭；开启后，同一个人或智能体不能既做又验证同一个任务。`alm redact` 从任务历史中删去某些字段的旧值，留下做过删除的记录，但不留旧值；法律保全期间会被拒绝。
- **监测开的终端标签页会自己关闭（macOS）。** 监测的任务完成后，它的 Terminal 标签页提示 30 秒后关闭；按任意键可以保留。Windows 上的监测窗口和以前一样保持打开。

## 其他

- **“显示”筛选面板有关闭按钮。** 标签页一行最右边的 **×** 收起面板，筛选保持不变。
