# 2026-11-15 讨论：一个队列装下所有要人做的事（A01-giant040）

任务：`A01-giant040`。用到 [0027](../decisions/0027-what-counts-as-high-risk.md) 的风险分级。

## 起点：现在的事实（2026-11-15）

- `alm human` 分三组：待检查 270 个任务、AI 决定待审 179 个（其中 162 个和待检查是同一个任务，合起来约 287 个任务）、待回答 1 个；事后待批准的紧急改动 0 个。
- 应用里没有专门的地方：要在任务列表里用筛选（如「人已检查：否」）挑出来，或逐个打开任务面板看。
- 还没有一个任务有风险分级（0027 的补分级还没做）。
- 完成的任务不会挡住别的任务；只有等人的事（待回答、待批准）会挡。

## 问与答

1. **队列放在哪里？** 批准者先问："我现在还不明白这个队列放在甚么地方？" 提议：应用窗口里一个新入口「待你处理」，和任务列表并列；点一行在右边打开任务面板；`alm human` 按同样顺序列出。批准者要看示意图（在对话里给了：顶部入口、左边排好序的清单、右边任务面板），问"如何切换到这个界面？"（答：顶部入口、菜单和快捷键、以后从提醒点进）。
   - 打开项目时先看到什么：批准者："保持现在的做法，先显示任务列表。"
   - 批准者："这代办列表界面，作成一个单独弹出的界面会比较好。"
   - 切换项目标签时：提议三种（跟着切换、每个项目一个窗口、所有项目合在一个窗口，第三种另开任务）。批准者："跟着切换可以。但还要考虑到，我可以把项目标签拖放成一个新窗口的情况"。提议：待办窗口只有一个，跟着你最后在用的那个主窗口里显示在前面的标签；点进待办窗口时它不换；标题写项目名（「待你处理 · <项目名>」）；拖出新窗口时跟过去；关掉它显示的项目就换成最后在用的主窗口的前面标签；所有项目都关了就关掉；前面是开始页时保持上一个项目。批准者："可以"。（由此，形式是单独的窗口，不是盖在上面的对话框。）
2. **队列的顺序和任务本身的顺序有关系吗？** 回答：基本没有。任务列表的顺序是计划（区域、迭代的先后）；队列的顺序是"你现在先处理哪件"（有没有代理在等你、风险、等了多久）。提议加一条最后的规则：前面都比不出先后时，按迭代在计划里的先后排。批准者："可以，加上这一条"。
3. **一行放什么、怎么排？** 提议：一个任务一行；有代理在等你的事一律排最前（先比挡住的任务数，再比等了多久）；做完待审的按风险 高 → 中 → 低 → 未分级，同级等得久的在前，最后按迭代先后；`alm human` 同样顺序。批准者："都可以"。
