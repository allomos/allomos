# 2026-09-27 — Kickoff discussion

Participants: will.w.hui (owner), Claude (Claude Code session).

## 1. Starting point

The owner wants to develop new software to manage the tasks, and their progress, that the owner works on with Claude and Codex. The `glidebox` folder was initialized as a git repository on `main`, using the same local git identity as `glidepace-vibe-cc` (`will.w.hui <willwhui@gmail.com>`). SSH to GitHub works (authenticates as `wanghui2sea`). **No remote has been added yet.**

## 2. First framing and the owner's correction

Claude's first framing: work is spread over terminals, branches and chats, and it is hard to see what is planned, in progress, done or waiting on the owner.

The owner said the problem is **more than that**, pointed to the SSR migration `TASK_BOARD.md` and its related files, and stated the requirements:

- See the **progress and state** of tasks, **grouped by workstreams**.
- Present them as **charts and lists**.
- A **burndown chart** that estimates the project's **finish time**. Reference: the burndown work in `glidepace-vibe-cc`.
- **Teammates collaborate online.**
- Remember the reference files and folders for later use.

## 3. Analysis

Claude read the board, a sample card, the workstream index, `ESTIMATE.md` and `AI-WORKFLOW.md`, and the burndown/forecast code in Glidelines. The full write-up is in [analysis/ssr-task-board.md](../analysis/ssr-task-board.md). Summary of the problems:

1. Status duplicated in about six places, kept in sync by hand.
2. Status is prose, not data.
3. The owner is the bottleneck (checks, approvals) with no queue.
4. Manual claiming through git commits and merge conflicts.
5. No forecast: estimates are per workstream and not tied to cards; the total scope is not on the board.
6. Expensive context for agents to resume.
7. No collaboration outside the repo.

Glidelines already has a `tasklist.json` format with workstreams, statuses and burndown history, a burndown with a reconstructed band for missing dates, and an estimate-based forecast. It also contains a one-shot converter for this same board (see [decision 0003](../decisions/0003-relationship-to-glidelines.md)).

## 4. Proposed direction

An online database as the shared source of truth; agents write structured status through a CLI / MCP server; data model Project → Workstream → Task with state, label ladder, claim, waiting-on, optional size and an event history; views for workstream lists, board, "waiting on me", progress charts, timeline and burndown with a forecast finish range; an importer for the existing board. Details are in [PLAN.md](../PLAN.md).
