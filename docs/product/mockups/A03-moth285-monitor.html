Mockup for task A03-moth285, as of 2026-11-04. The written specification in the task's description is the authority; this page only shows it. Open question at the time of saving: the approver asked for each task to run in a new session, which may move the monitoring from an agent session into the app (see the task).

Recommendation: one project-level button in the top bar, with a which-tasks choice in its dialog (the Iterations tab is always there), plus the same button on the active iteration's card (the Iterations tab has no top-bar button). Both open the same dialog. Task A03-moth285 (backlog).

1 · The button and its dialog every project

The Iterations tab is always there, so the dialog always has the same “处理哪些任务” field. It starts on the active iteration when there is one and on “全部就绪任务” when there isn't. Someone who never uses iterations only ever sees “全部” chosen; someone whose iterations came from “构建新应用…” gets a one-line explanation.

No top-bar button on this tab. Only the active iteration's card has the button, with the same words “▶ 自动监测就绪任务”; it opens the dialog from mockup 1 with “当前迭代” picked. Other iterations have no button (they can still be chosen in the dialog from the other tabs). With no active iteration, this tab shows no monitor button at all. While a run is going, its status bar takes the button's place in the active card.

4 · Starting, running, waiting, stopping

The button turns into a status bar: “监测中” and what the agent is doing, then the check interval (click to change it), then the “Claude Code · I-haul” session link (drawn like the task list's holder link), then “停止”. When nothing is ready the agent waits and checks again at the interval; the bar shows the next check time and “↻ 立即检查”. The agent waits inside alm run wait, which returns at once when the person presses 立即检查, changes the interval or presses 停止, so all three take effect immediately. “停止” is graceful while a task is being worked. “↺ 撤销停止” withdraws it. On the Iterations tab the bar sits in the active iteration's card.
